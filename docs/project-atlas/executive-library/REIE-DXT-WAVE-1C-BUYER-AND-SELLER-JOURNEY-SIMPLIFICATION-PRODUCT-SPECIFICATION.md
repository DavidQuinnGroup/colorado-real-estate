# REIE DXT Wave 1C Buyer And Seller Journey Simplification Product Specification

Program: REIE Decision Experience Transformation (DXT 1.0)

Phase: Wave 1C - Buyer and Seller Journey Simplification Product Specification

Status: `REIE_DXT_WAVE_1C_BUYER_AND_SELLER_JOURNEY_SIMPLIFICATION_SPECIFICATION_COMPLETE`

Date: August 2, 2026

## 1. Executive Product Decision

The selected first Wave 1C phase is:

`BUYER_SELLER_SHARED_HIERARCHY_FOUNDATION`

Wave 1C should not begin with two separate runtime implementations. The Buyer and Seller journeys share the same core problem: both should inherit the DXT decision architecture established by Homepage Wave 1A before either page receives isolated refinement.

Implementation is not authorized by this specification.

## 2. Governing Wave 1C Question

What decision is this customer trying to prepare for, and what should they do next?

Buyer and Seller pages should stop behaving like general educational documents and become decision journeys with:

- one primary question;
- one clear opening promise;
- a small number of preparation steps;
- visible boundaries around what requires professional verification;
- a calm advisory transition.

## 3. Buyer Customer Problem

The Buyer journey currently contains valuable guidance, including Buyer Readiness and Buyer Financing Decision Planner continuity, but it risks becoming a collection of helpful modules rather than one clear decision path.

The customer problem:

- Am I prepared to search, compare, and pursue a property responsibly?
- What assumptions are still unresolved?
- What should I verify before pressure increases?
- When should financing, property review, and advisory conversation enter the process?

The Buyer journey should not become:

- a loan application;
- a qualification or approval tool;
- a buying-power engine;
- a property recommendation engine;
- a generic buyer education article.

## 4. Seller Customer Problem

The Seller journey contains useful readiness and evidence concepts, but the customer needs clearer sequencing from preparation to market conversation.

The customer problem:

- What should I understand before pricing and launch pressure take over?
- What property facts, buyer objections, and evidence gaps should be organized?
- How should seller readiness connect to advisory conversation?

The Seller journey should not become:

- an automated valuation engine;
- a listing-price recommendation;
- a guarantee of buyer behavior;
- a replacement for professional pricing, legal, tax, condition, or disclosure review.

## 5. Buyer Inventory And Dispositions

Current repository-supported Buyer concepts include:

- Buyer Readiness;
- Financing Readiness;
- Buyer Financing Decision Planner;
- Search continuity;
- Decision Journey continuity;
- Advisory Handoff;
- public trust and professional-boundary language.

Disposition:

| Buyer element | Disposition | Reason |
| --- | --- | --- |
| Buyer page orientation | SIMPLIFY | Must state the buyer decision immediately. |
| Buyer Readiness content | KEEP_AND_RESEQUENCE | Valuable, but should follow a decision-first hierarchy. |
| Financing Readiness | KEEP_WITH_BOUNDARY | Certified planner remains bounded and should not dominate the entire Buyer journey. |
| Search continuity | KEEP_AND_ELEVATE | Search is the primary discovery surface after preparation. |
| Advisory transition | KEEP_AND_CLARIFY | Advisory should feel like prepared conversation, not generic contact. |
| Dense education blocks | MERGE_OR_MOVE_LOWER | Useful only when tied to the customer decision. |
| Qualification or affordability implications | PROHIBIT | Conflicts with certified financing boundaries. |

## 6. Seller Inventory And Dispositions

Current repository-supported Seller concepts include:

- Seller Readiness;
- Property / Seller Evidence;
- market context;
- buyer questions and preparation;
- Advisory Handoff;
- public trust and professional-boundary language.

Disposition:

| Seller element | Disposition | Reason |
| --- | --- | --- |
| Seller page orientation | SIMPLIFY | Must state the seller decision immediately. |
| Seller Readiness | KEEP_AND_RESEQUENCE | Valuable when it leads to a clear preparation path. |
| Property / Seller Evidence | KEEP_WITH_BOUNDARY | Should organize evidence gaps without creating legal, title, valuation, or disclosure conclusions. |
| Market context | KEEP_LOWER | Useful after preparation has been framed. |
| Advisory transition | KEEP_AND_CLARIFY | Seller needs a prepared professional conversation. |
| Automated valuation language | PROHIBIT | Conflicts with trust and professional-boundary model. |
| Dense explanatory blocks | MERGE_OR_MOVE_LOWER | Must earn place by improving seller decision quality. |

## 7. Target Buyer Journey

Target sequence:

1. Page orientation.
2. Governing buyer question.
3. Opening promise.
4. Preparation themes.
5. Search and comparison transition.
6. Financing Readiness boundary and planner entry.
7. Property questions to verify.
8. Advisory transition.
9. Research continuations.

Buyer decision question:

`Am I prepared to search, compare, and pursue a home with the right assumptions and verification plan?`

## 8. Target Seller Journey

Target sequence:

1. Page orientation.
2. Governing seller question.
3. Opening promise.
4. Preparation themes.
5. Property and evidence gaps.
6. Market context.
7. Buyer-objection preparation.
8. Advisory transition.
9. Research continuations.

Seller decision question:

`What should I understand and organize before pricing, preparation, and market launch become urgent?`

## 9. Shared Hierarchy Model

Buyer and Seller should inherit the same DXT hierarchy:

1. orientation;
2. primary decision question;
3. concise promise;
4. three to five preparation themes;
5. relevant tool or journey continuation;
6. questions to verify;
7. trust and professional boundaries;
8. advisory transition;
9. compact continuations.

Shared implementation rules:

- one dominant action per major viewport;
- less explanatory copy above the fold;
- no equal-weight card wall for every available concept;
- no hidden personalization, persistence, scoring, or readiness label;
- no broad route or navigation change.

## 10. Density Reduction Model

Wave 1C should reduce density by:

- making the primary question explicit;
- shortening section introductions;
- grouping preparation themes;
- moving secondary education lower;
- using prompt-only verification questions;
- keeping continuation links compact;
- avoiding dashboard, portal, scorecard, and intake-workflow presentation.

Every future section must pass:

`If this disappeared, would the customer make a worse decision?`

If the answer is no, the section should be removed, merged, moved lower, or moved to a destination page.

## 11. Buyer Financing Boundary

Buyer Financing Decision Planner remains certified as:

- user-entered assumptions only;
- educational arithmetic only;
- no provider;
- no persistence;
- no qualification;
- no approval;
- no affordability or buying-power conclusion;
- no lender, rate, or loan recommendation.

Wave 1C may improve how the Buyer journey introduces the planner, but it must not change planner arithmetic, provider posture, persistence posture, or professional-boundary language without a separate authorization.

## 12. Seller Valuation Boundary

Wave 1C must not create:

- automated valuation;
- price recommendation;
- listing strategy recommendation;
- investment projection;
- tax advice;
- legal advice;
- guaranteed market outcome;
- buyer-behavior prediction.

Seller experience may prepare valuation questions and evidence gaps, but final pricing and professional review remain outside automated public conclusions.

## 13. Property / Seller Evidence Boundary

Property / Seller Evidence may support:

- organization of known facts;
- identification of gaps;
- professional verification prompts;
- advisory preparation.

It must not determine:

- legal status;
- ownership;
- title;
- permits;
- zoning;
- HOA obligations;
- condition;
- environmental risk;
- insurance eligibility;
- disclosure sufficiency;
- suitability;
- valuation certainty.

## 14. Fair-Housing And Steering Boundary

Wave 1C must not introduce:

- demographic targeting;
- protected-class proxies;
- family-status steering;
- school rankings;
- safety or crime rankings;
- socioeconomic comparisons;
- desirability claims;
- "best" or "ideal for" language;
- suitability conclusions.

## 15. CTA Model

Buyer CTA hierarchy:

- primary: continue to Search or buyer preparation depending on viewport purpose;
- secondary: review financing readiness;
- tertiary: advisory conversation.

Seller CTA hierarchy:

- primary: prepare seller questions or continue seller guidance;
- secondary: review market context;
- tertiary: advisory conversation.

CTA constraints:

- no dense CTA clusters;
- no provider, lender, scheduling, upload, CRM, application, or qualification CTA;
- no hidden transfer of customer state.

## 16. Mobile Model

At approximately `390x844`:

- use a single-column decision narrative;
- expose the primary question early;
- present preparation themes before dense links;
- keep financing/evidence boundaries adjacent to related content;
- stack continuations;
- avoid long card walls;
- maintain stable touch targets;
- avoid intake-portal, dashboard, scorecard, or financial-institution appearance.

## 17. Desktop And Tablet Model

At tablet and desktop sizes:

- use restrained widths;
- preserve editorial pacing;
- use two-column layouts only for complementary content;
- avoid excessive empty regions;
- keep journey sequencing obvious;
- keep continuation links low-density.

## 18. Accessibility Requirements

Wave 1C implementation must preserve or improve:

- semantic headings;
- logical reading order;
- keyboard operation;
- visible focus states;
- accessible link names;
- readable disclosures;
- no color-only status;
- touch target stability;
- reduced-motion compatibility where relevant.

## 19. First Implementation Phase

Selected first phase:

`BUYER_SELLER_SHARED_HIERARCHY_FOUNDATION`

Purpose:

- establish the shared Buyer/Seller decision hierarchy before separate page-specific runtime work;
- define exact content dispositions for both pages;
- prevent inconsistent Buyer-only or Seller-only refinements;
- keep runtime implementation bounded when later authorized.

This phase should be a bounded implementation planning gate before any Buyer or Seller runtime edit.

## 20. Wave 1C Implementation Sequencing

Recommended sequence:

1. `BUYER_SELLER_SHARED_HIERARCHY_FOUNDATION` planning and specification approval.
2. Buyer page bounded implementation, if authorized.
3. Seller page bounded implementation, if authorized.
4. Local certification and push review for each runtime phase.
5. Production certification under separate authorization.
6. Program closure only after both authorized surfaces pass certification or the program is explicitly narrowed.

No combined Buyer/Seller runtime commit should be assumed unless separately authorized and file-scope risk remains low.
