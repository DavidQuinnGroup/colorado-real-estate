## 3. Contract Model

Selected model:

`DOCUMENTATION_AND_DETERMINISTIC_CONTRACT_ONLY`

The contract is intentionally page-independent. It defines the structure future Buyer and Seller phases must respect without forcing either page into identical content or premature component abstraction.

## 4. Canonical Hierarchy

The canonical hierarchy for future Buyer/Seller implementation phases is:

1. page orientation;
2. governing decision question;
3. concise opening promise;
4. preparation themes;
5. tool or evidence continuation;
6. questions to verify;
7. professional and trust boundaries;
8. advisory transition;
9. compact next-decision continuations.

## 5. Current Runtime Relationship

Current runtime surfaces were inventoried but not modified:

- `app/buy/page.tsx`
- `app/sell/page.tsx`

The current Buyer page already contains buyer confidence orientation, Search continuation, financing readiness, market continuation, and advisory guidance.

The current Seller page already contains seller strategy orientation, preparation priorities, market context, home-worth continuity, seller readiness, contact routing, and advisor review.

This implementation does not certify current Buyer or Seller runtime pages against the future hierarchy. It establishes the contract that future bounded runtime phases must use.
