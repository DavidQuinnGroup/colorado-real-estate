# REIE Product Experience North Star

Program: REIE Product Experience, Capability, and Master-Vision Reconciliation

Date: 2026-08-18

Status: `EXECUTIVE_PRODUCT_EXPERIENCE_NORTH_STAR_ADOPTED_FOR_RECONCILIATION`

## Governing Direction

PROJECT ATLAS / REIE should ultimately present the complexity of the
intelligence engine through an interface with Apple-level product discipline.
The governing question is:

> If the complexity of PROJECT ATLAS disappeared behind an interface designed
> with Apple's discipline, what would the user experience become?

This is a product-experience direction, not a visual redesign authorization.
Current certified architecture and adopted executive decisions remain the
authority for current behavior. Capability and information architecture
reconciliation precede any shell redesign.

## Desired Experience Characteristics

- Immediate comprehension and strong spatial hierarchy.
- Progressive disclosure and intuitive navigation.
- Minimal cognitive load with intentional typography and whitespace.
- Contextual intelligence surfaced at the decision moment.
- One obvious next action where appropriate.
- Consistent interaction grammar across REIE capabilities and Hubs.
- Meaningful state and motion feedback.
- First-class mobile experience, accessibility, readable contrast, and fast
  performance.
- Deep capability without exposing architectural complexity.

## Same-Page Decision Continuity Principle

When a user is making selections, configuring criteria, answering questions,
applying filters, or progressively building context for one task, the resulting
intelligence should normally appear on that same page. The inputs remain
visible and editable so the user can see what produced the output, make an
adjustment, and update the result without losing orientation.

The preferred interaction is:

`CHOOSE -> SEE -> UNDERSTAND -> ADJUST -> SEE THE EFFECT`

This is an explainability standard, not merely a navigation preference. The
relationship between an explicit input and ATLAS output should remain visually
understandable wherever the task is progressive and the output can be updated
in place.

A route transition remains appropriate when the user intentionally begins a
different canonical task or object, such as opening a specific Property,
moving from Buyer Preparation to Property Preparation, opening a dedicated
Market product, or entering a distinct administrative capability. This
principle does not require a broad retrofit of existing products.

## Future Visual Direction

The future visual direction is:

`Apple-inspired product discipline + Glassmorphism / Glassmorphic visual language + Liquid-Glass-inspired depth, translucency, layering, hierarchy, and motion`

This direction is deliberately subordinate to information architecture,
readability, accessibility, performance, and decision clarity. It does not
authorize copying proprietary assets, cloning Apple interfaces, imitating
protected trade dress, or introducing glass effects before capability
reconciliation.

## Reconciliation Rules

1. Identify the customer question and the decision moment before choosing a
   surface or visual treatment.
2. Separate current certified behavior from intended V7.1 or later vision.
3. Preserve later certified architecture and executive decisions when they
   supersede older Master concepts.
4. Prefer one coherent customer journey over a collection of disconnected
   capability demonstrations.
5. Make evidence, freshness, limitations, and professional handoff visible at
   the point where they affect reliance.
6. Treat mobile, accessibility, contrast, performance, and failure states as
   part of product quality rather than finishing work.
7. Do not use visual polish to conceal incomplete functionality, weak evidence,
   unclear ownership, or unresolved governance.
8. Preserve same-page decision continuity for progressive tasks unless a
   distinct canonical workflow or object requires a route transition.

## Non-Authorization Boundary

This record authorizes no route redesign, navigation refactor, component-shell
rewrite, CSS migration, glass effect, animation system, provider integration,
data retrieval, database or schema change, Search or Typesense mutation,
customer-data mutation, CRM or email behavior, deployment, or production
activation.
