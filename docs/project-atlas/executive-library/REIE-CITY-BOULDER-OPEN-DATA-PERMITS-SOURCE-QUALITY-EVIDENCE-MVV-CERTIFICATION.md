# REIE City Boulder Open Data Permits Source Quality Evidence MVV Certification

## Scope

This MVV certifies a source-specific, certification-only Source Quality evidence package for:

`SRC-CITY-BOULDER-OPEN-DATA-PERMITS`

It does not retrieve, inspect, parse, activate, redistribute, display, or legally approve Open Data or permit content.

## Canonical conversion

The package uses `convertPublicRecordStructuredEvidence` with source class `MUNICIPAL_OPEN_DATA_PERMIT` and the exact source confirmation. It produces one canonical certification linkage and flows through Evidence Normalization, Source Quality Control, and Summary Assembly.

## Structured input

The sole evidence input is a controlled `CERTIFICATION_REFERENCE` bound to the exact source ID. It contains no Open Data content, terms, endpoint data, narrative, correspondence, or raw records.

## Evidence posture

- Field sensitivity: `IDENTIFIER_BEARING_CONTEXT` as governance metadata only.
- Rights: `UNKNOWN`.
- Technical access: `UNKNOWN`.
- Freshness: `UNKNOWN`.
- Attribution: `UNKNOWN`.
- Provenance: `UNKNOWN` / incomplete.
- Normalization and Control: `INSUFFICIENT_EVIDENCE` with preserved known gaps.
- Assembly: accepted as a sparse one-source request.
- Eligibility: `READY_WITH_KNOWN_GAPS`.

Eligibility means the source has bounded, independently governed evidence suitable for later Source Quality and Manifest decision review. It does not mean provider confirmation, unrestricted reuse, redistribution, automation, API access, currentness, legal approval, activation, retrieval, scraping, or customer display.

## Registry and channel boundaries

Registry posture remains `AWAITING_PROVIDER_CONFIRMATION`, `BLOCKED_NOT_AUTHORIZED`, and claim-ineligible. Evidence does not alter Registry authority. Evidence is not inherited from the City building-permit portal, Boulder County Accela, Permit Candidates, Assessor, or Treasurer sources.

## Protected boundaries

No Open Data system, City website, endpoint, API, download, correspondence, PDF, protected county artifact, database, provider, credential, CRM, Search, Typesense, route, or UI is used.

## Later work

Any future finite human-reviewed findings remain separate. Any Operational Manifest inclusion requires a separate decision review.
