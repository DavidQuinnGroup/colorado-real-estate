## Purpose And Scope

This is the governing design-architecture reference for future PROJECT ATLAS
visual and user-interface work. It defines information hierarchy, shell and
navigation architecture, page families, material hierarchy, semantic token
architecture, interaction semantics, responsive and accessibility behavior,
data presentation, design-system governance, migration sequencing, and human
certification expectations.

It is not runtime implementation, a CSS or Tailwind specification, a data or
schema contract, a route-migration authorization, a deployment authorization,
or authorization to activate a provider, source, client workflow, or external
action.

## Precedence And Boundaries

This architecture remains subordinate to applicable law and regulation,
mandatory brokerage policy, source and licensing rights, professional-scope
boundaries, later explicit Executive decisions, and current certified
product/data architecture. Within design matters, later explicit Executive
design disposition controls earlier design recommendation, which controls
legacy or transitional visual implementation. Design never overrides canonical
product/data ownership.

The architecture composes certified foundations. It does not create a new
Grand Plan, appraisal, financial, senior, strategy, master-app, Sundance,
personal-authority, Client Case, Transaction, or Output root.

## Design System Identity And North Star

`PROJECT_ATLAS_LIQUID_GLASS_DESIGN_SYSTEM_V1` governs one shared brand,
semantic language, interaction model, accessibility foundation, component
family logic, and responsive model across context-specific shells. It does not
mean that runtime components already conform.

PROJECT ATLAS is a premium, calm, intelligent, evidence-aware Colorado real
estate intelligence and advisory system. Its Liquid Glass language is modern,
spatially layered, precise, high-trust, professional, and distinctly premium;
orientation, hierarchy, legibility, actionability, accessibility, performance,
and analytical clarity always take precedence over decorative translucency.

## Design Principles

1. Orientation before decoration.
2. Hierarchy before containers.
3. Glass is a material, not a gimmick.
4. Dense data gets stable contrast.
5. Page titles are never optional.
6. Major sections must be scannable.
7. Clickable things look clickable.
8. Use one primary action per local decision area where practical.
9. Global domain and Client Case context remain distinct.
10. Facts, assumptions, models, Professional Input, editorial context, and Agent opinion remain distinguishable.
11. Professional boundaries constrain claims, not analytical depth.
12. Public authority is useful before it is optimized for search.
13. Mobile is a designed experience, not shrunk desktop.
14. Accessibility is foundation, not polish.
15. Progressive disclosure hides complexity, not primary context.
16. Compose before duplicate.
17. Status requires more than color.
18. Client-facing Output is not the Agent Workspace.
19. Current product truth outranks legacy route accidents.
20. Human certification is part of design completion.

## Anti-Pattern Register

The following are prohibited or strongly discouraged: card soup; nested-card
stacks; low-contrast glass; glass everywhere; tiny gray headings; a hero
replacing a page title; ambiguous clickable text; no pointer on a clickable
control; hidden active-client context; arbitrary domain as Agent Home; rainbow
domain design; opaque universal scoring; forced redirect after selection;
arbitrary topic caps; forced registration before public value; pill-everything;
technical database terminology as primary UI; mobile as shrunk desktop; SEO
link farms; color-only status; uncontrolled text over image; every action as
primary; every page as a unique component system; and big-bang visual rewrite
without certification.

## Information Hierarchy

Canonical hierarchy, from highest to lowest prominence:

1. Display or hero
2. Page title
3. Page context or subtitle
4. Major section
5. Subsection
6. Panel or card title
7. Body emphasis
8. Body
9. Field label
10. Help or metadata
11. Caption

Page titles are visually dominant. Major sections use scale, weight, spacing,
contrast, or structural separation sufficient for rapid scanning. Subsections
remain visibly above panel content. Field labels are persistent and functional;
metadata is subordinate. A CTA, hero slogan, breadcrumb, eyebrow, status pill,
or domain label cannot replace a substantive page title.

Human hierarchy certification asks whether a user can identify the page title
within one second, scan major sections without reading body copy, distinguish a
subsection from a panel title, find the section action, and identify version or
current-state regions. A material failure fails hierarchy certification.

### Public Shell

The Public shell serves discovery, authority, property/place search, education,
local intelligence, and professional trust. It uses richer premium editorial
glass only where appropriate, lower-to-moderate density, intent-oriented public
navigation, a persistent Home path, and a discoverable Agent login. Private
Agent controls are never exposed.

### Agent Shell

The Agent shell serves professional work, Client Case work, analysis, review,
decision support, Transaction work, and Output work. It uses restrained
analytical glass and moderate-to-high density. Its global navigation is grouped;
its Client Case context is explicit and persistent where applicable. Agent
Workspace Home and Public Site return remain durable paths.

### Client Private Shell

The Client Private shell serves shared decisions, reviewed Outputs,
authorization, secure actions, and next steps. It uses premium calm glass at
lower density than Agent. Agent internal controls and Admin controls are not
exposed. Client-private orientation is explicit and scoped.

### Admin Shell

The Admin shell serves system governance, source state, health,
administration, and operational controls. It uses a minimal utilitarian
expression of the shared system and may be high density. It is not the primary
place for Agent professional work.

## Navigation And Orientation

Public primary navigation is intent-oriented: Search, Buy, Sell, Market, and
Grand Plan. Home Worth, About, Contact, Trust & Methodology, legal, privacy,
and accessibility remain secondary, contextual, or footer routes as
appropriate. Public Home is a persistent orientation path.

Agent global navigation is grouped around Workspace, Client Work, Preparation,
Strategy, Transactions, Outputs, Intelligence/applicable governed domains,
Admin/MCP access where permitted, and Public Site return. It must not depend
indefinitely on one flat row that exposes every domain. Agent Workspace Home is
a persistent operating landing; browser Back is not primary navigation.

Client Private and Admin navigation remain scoped to authorization and role.
Public-to-Agent and Agent-to-Public transitions are deliberate, visible, and
never dependent on browser history.

## Client Case Context

Client Case context is visible, not global hidden state. A persistent contextual
region may show Case identity, journey/role, status, subject Property,
Transaction context, attention state, and contextual navigation. Client Case is
not Transaction; Property, scenario, decision, authorization, evidence, and
Output retain their own identities and may be composed through explicit links.

Existing Case Transactions receive stronger operational prominence than Create
Transaction when a Case already has Transactions. Creation remains a bounded
secondary action.

## Agent Workspace And Preparation

Agent Workspace Home prioritizes resuming durable Client Work, review-required
work, explicit bounded new-work entry, and current attention. It is not a
generic dashboard for every internal capability.

Preparation pages follow purpose, current context, questions/tasks,
evidence/assumptions, bounded recommendation, and next action. Preparation
uses clear substantive titles and major sections. Location preparation retains
clear naming; selection remains on-page rather than forcing a redirect; topics
are not capped arbitrarily; expandable controls accurately reflect their
collapsed or expanded state.

## Property, Search, And Map

Search is a dedicated property/place workspace with a clean initial state,
meaningful search input before results where appropriate, address/property
discovery, common and advanced filtering, map/list synchronization, retained
selection, comparison, evidence cues, and deliberate next steps. Active filter
state, clear-one, clear-all, collapsed state, mobile behavior, and meaningful
collapsed summaries must be visible.

Map overlays are restrained. Property pages combine discovery context,
property-specific evidence, limitations, comparison, and next questions without
claiming unsupported certainty. Public Search, Agent retrieval, future Agent
command, and Client-private search are separate architectures.

## Financial, Market, And Decision Architecture

Financial surfaces distinguish scenarios, assumptions, sensitivities,
uncertainty, and comparisons from governed facts and verified Professional
Input. Scenario versions are visibly current, immutable where applicable, and
discoverable during rapid scanning. Financial and multi-property analysis stay
within certified foundations; no monolithic financial root or professional
underwriting conclusion is created.

Market surfaces organize state, city, neighborhood, and property context from
orientation to evidence. Every metric has definition, unit, date/interval,
source/effective date where appropriate, and limitation context. Filter state
explains constrained results. Up and down are neutral comparative directions
unless the analytical context establishes value.

Decision products use this reusable hierarchy: Decision Question, Context, Key
Evidence, Options, Financial Impact, Market Impact, Tradeoffs, Uncertainty,
Agent Recommendation, Next Action, and Related Output. Agent recommendation
separates judgment, evidence, tradeoffs, alternatives, and next action; it is
not algorithmic certainty.

## Transaction, Output, And PDF

The certified Transaction root remains distinct from Client Case, Property,
scenario, decision, and Output. Transaction pages may present identity, Case,
Property, lifecycle/status, current milestone, timeline/history, current action,
related Outputs, and future seams for documents, deadlines/tasks, and advisory
lineage. Unimplemented seams are not presented as active.

Output experiences distinguish creation, review, version history, render/PDF,
delivery/sharing, client output, and provenance/evidence. Decision is working
intelligence and recommendation lifecycle; Output is reviewed communication.
Agent working controls never become the client communication view.

PDF/print is a separate print-first sibling system. It shares brand,
typographic and information hierarchy, semantic status/chart/evidence language,
but does not rely on transparency, blur, hover, disclosure, screen navigation,
or dynamic backgrounds.

## Professional Input, Evidence, And Secure Actions

Professional Input, Evidence Candidate, Evidence Admission, and materialized
Professional Input are distinct governed states. Interfaces show provenance,
review/admission state, source limits, and the absence of automatic admission.

Client Authorization and secure action flows remain scoped, quiet, token-free
after access exchange, and explicit about what opening, confirming, declining,
or completing does and does not do. Client-private surfaces never expose Agent
or Admin controls.

## Life Transition, Event, And Public Authority

Life Transition Planning is an opt-in composed experience based on certified
foundations. It must not infer sensitive needs from age or proxy, steer on
protected characteristics, or offer medical, care-suitability, tax, or legal
conclusions. Legacy/heir concepts remain later secure-governance seams.

Event & Lifestyle and Sundance are reusable editorial architectures with source
boundaries, limitations, and contextual navigation. They do not assume live
feeds, live data, or deterministic event yield.

Public Authority composes place, property/market, decision education, event and
lifestyle, editorial, professional authority, Trust & Methodology, and Search
discovery without disconnected products. Place experience prohibits demographic
steering, protected-class ranking, or “best for” protected-group claims.

`LG-03` establishes one composed `Trust & Methodology` public destination with
contextual deep links from evidence, freshness, privacy/security, professional
boundaries, methodology, and footer/legal surfaces. It explains sources,
classes, freshness, methodology, modeled versus verified information,
professional boundaries, limitations, accessibility, and relevant legal
context without exposing security-sensitive, protected, restricted, private, or
proprietary information.

## Spacing, Border, Radius, And Depth

Use a compact, semantic spacing scale and stable component dimensions. Radius
is restrained: 2px, 4px, 6px, and 8px are the default design-system steps;
larger curvature requires an explicit product reason. Borders communicate
surface, grouping, status, and focus without creating decorative container
stacks. Depth is shallow and semantic: it distinguishes shell, contextual
region, and active action, not every panel from every other panel.

## Actions, Forms, Tables, Metrics, And Charts

Action roles include primary, secondary, tertiary/ghost, inline link,
navigation link, icon action, destructive action, download/export, secure
action, and external link. Use one primary action per local decision area where
practical. Semantic interactive controls require a pointer cursor, visible
hover/focus/pressed/selected behavior, and distinct disabled/loading/destructive
states.

Forms support persistent labels, required/optional state, current value, unit,
help, validation, error, source/provenance where relevant, and save state.
Placeholder-only labels are prohibited. Units are explicit for currency,
percent, months, years, square feet, beds, baths, dates, rates, and other
domain measures.

Tables support clear headers, appropriate sorting/filtering/selection,
responsive behavior, loading/empty state, sticky context where useful,
accessible reading order, and tabular numerals. Mobile strategies include
purposeful horizontal scroll, priority columns, expandable rows, card
transformation, or sticky key columns; text is not shrunk into illegibility.

Metrics show title, primary value, unit, comparison delta, interval,
definition/help, and source/effective date where needed. Charts state a clear
question, title, units, date interval, legend as needed, source/methodology,
accessible interpretation, mobile strategy, and print strategy. Use chart plus
table where pattern and exact values are both useful; do not force a chart when
a table communicates the result better.

## Information-Class And State Semantics

| Class | Required expression |
| --- | --- |
| Governed fact | Source/provenance, date basis, and neutral confidence context |
| Assumption | Explicit assumption label and reviewable input context |
| Modeled result | Calculation/model label, inputs, and uncertainty |
| Professional Input | Source identity, verification and review/admission state |
| Editorial context | Editorial framing, distinct from evidence |
| Agent opinion | Identified judgment, supporting evidence, and limits |
| System status | Lifecycle label plus plain-language state |
| Warning/limitation | High-contrast limitation and next verification step |

Status, alert/notice, empty, loading, error, partial/stale-data, and provenance
states must communicate meaning with text, iconography, and structure rather
than color alone. Empty states name scope and the next safe action. Loading
preserves layout. Errors avoid internal detail. Partial data distinguishes what
is available from what remains unverified. Output, authorization, evidence, and
other lifecycle states use their actual canonical repository values rather than
invented design-only state names.

## Responsive, Accessibility, Privacy, And Motion

Public mobile uses compact disclosure navigation with durable Home and Search.
Agent mobile uses a collapsible grouped drawer with persistent Case context,
not a crowded global row. Client and Admin mobile navigation remain scoped to
their role. Sticky UI is used only when it preserves context or a bounded action
without obscuring content.

Accessibility is foundational: semantic headings, keyboard traversal, visible
focus, contrast, reduced motion, non-color signaling, persistent labels,
accessible chart/table alternatives, and opaque glass fallback are required.
Low-contrast glass is prohibited.

Motion is limited, purposeful, and removable through user preference. No
critical action depends on animation. Security and privacy language explains
scope, authorization, lifecycle, and consequences without revealing sensitive
implementation detail.

Modals are reserved for bounded, interruptive decisions. Drawers preserve
navigation or inspection context without hiding the active task. Tabs represent
peer views of a stable object; they do not substitute for page hierarchy or
global navigation. Selection, comparison, saved/favorite, recent-work, and
global-create patterns retain explicit scope and never imply a hidden active
Client Case.

## Brand, Photography, Map, And Public Contact

Brand expression remains one shared PROJECT ATLAS system with applicable
Compass co-branding and brokerage attribution preserved according to policy.
Photography is purposeful, legible, rights-aware, and never substitutes for

property, comparison, context, and accessible alternatives over decorative

Public lead capture, contact, and authentication remain contextually bounded:

not claim unavailable channels or unapproved service levels.

## Design System Governance And Visual Regression

Foundation tokens cover color, typography, spacing, radius, border, depth,
motion, focus, breakpoint, shell, surface, action, field, status, evidence,
data visualization, and print semantics. Component tokens are local extensions,
not new global meanings. Canonical component families are shell/navigation,
page header, section heading, action/link, field/form, disclosure,
status/evidence, metric/table/chart, state panel, Case context, decision panel,
Output canvas, and secure confirmation.

`LG-05` requires local repository-compatible visual baseline first where
practical. External visual-regression provider selection, paid service, and
purchase are not authorized. A future provider review is permitted only when a
local baseline proves insufficient or coverage/operational efficiency justifies
a separately authorized decision.

`LG-04` preserves a future permission-aware Agent command palette/quick
switcher after retrieval taxonomy for Client Case, Property, Transaction,
Output, and applicable domains is stable. It is not foundation work and cannot
create hidden context, permission bypass, Admin bypass, or ambiguous destructive
execution.

## Human Certification

Every future implementation wave requires human certification proportional to
its surface: page title and section scanning; pointer/disabled/action behavior;
keyboard, focus, and contrast; mobile layout; selected Case continuity;
information-class distinction; print where relevant; no unintended mutation;
and workflow-specific proof for protected actions. A design wave is not
complete merely because automated checks pass.
